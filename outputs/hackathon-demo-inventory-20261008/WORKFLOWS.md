# 시연 업무 이력 주입

기존 43건의 시연 재고가 설치된 demonstration 서버 DB에 들어간 상태에서 실행한다.
같은 디렉터리의 `inventory-example.csv`와 `workflow-manifest.json`을 읽는다.

```sh
sh outputs/hackathon-demo-inventory-20261008/seed-workflows.sh
```

스크립트는 계획 파일 검사, DB 사전 점검, 단일 트랜잭션 적용, 적용 후 검증을 순서대로 수행한다.
설치된 DB의 런타임 자격 증명은 systemd를 통해 읽으므로 `sudo` 암호가 필요할 수 있다.
같은 시나리오가 이미 적용되었다면 업무 데이터는 추가하지 않고 기존 결과를 검증한다.
주입 전에 완성된 통계 스냅샷이 남아 있다면 `apply` 단계에서 해당 스냅샷을
`SUPERSEDED`로 전환한다. 기본 통계 화면은 즉시 현재 원장을 실시간 집계하고,
다음 일별 통계 작업에서 새 스냅샷을 생성한다.

주입되는 이력:

- 기존 재고 43건: 공급처·매입가·매입 확정일·보증·매입 검수 보강
- 과거 판매용 재고 24건: 매입·검수·주문·재고 이동·판매 이력
- 기존 배송 단계 재고 14건: 주문·할당 연결, 그중 배송 완료 2건에 판매 이력
- 과거 판매 중 반품 4건, 교환 요청 1건
- 기존 판매 가능 재고 8건: 진행 중인 주문

적용 후 시연 DB에는 이 시나리오 기준으로 재고 67건, 매입 검수 67건과 반품 검수 4건,
주문·할당 46건, 판매 26건이 있게 된다. 통계 화면의 기본 조회 기간은 전체 이력과
다르므로 화면 수치가 이 총계와 같을 필요는 없다.

시연용 가상 고객·공급처·IMEI를 사용하며 외부 판매 채널 API는 호출하지 않는다.
사전 점검에서 원본 PG, SKU 잔고, 기존 할당이나 사용자가 수정한 매입 정보가 예상과
다르면 적용하지 않는다. 설치된 서버에서의 실행 결과는 `--verify` 출력으로 확인한다.
